# 环境配置与镜像源

主要内容：

- `apt / brew`、`conda`、`pip` 分别负责什么
- 下载慢时先从哪里入手
- 需要换源时怎么做

## 不同命令的分工

### `apt` / `brew`

负责系统工具，例如：

- `git`
- `curl`
- `wget`

结论：

不要用 `pip` 去装 `git`。

### `conda`

负责建立项目的 Python 环境，例如：

- 指定 Python 版本
- 隔离不同项目依赖
- 管理环境本身

结论：

不要把所有项目都装到 `base` 里。

### `pip`

负责安装当前项目的 Python 依赖，例如：

- `streamlit`
- `numpy`
- `requests`

结论：

推荐顺序始终是：

`先建 conda 环境 -> 再激活 conda 环境 -> 再 pip install`

## Ubuntu / WSL 里的系统工具安装

```bash
sudo apt update
sudo apt install -y git curl wget
```

这一步是系统层，不是 Python 层。

## macOS 里的系统工具安装

```bash
brew install git wget
```

如果你只是需要网络检查工具，`curl` 一般已经自带。

## Miniconda 安装

如果老师没有提供本地安装包，最常见的安装方式是：

```bash
cd ~
wget https://repo.anaconda.com/miniconda/Miniconda3-latest-Linux-x86_64.sh
bash Miniconda3-latest-Linux-x86_64.sh
source ~/.bashrc
conda --version
```

如果你已经安装了 Miniconda，但 `conda activate` 失败，先执行：

```bash
conda init bash
source ~/.bashrc
```

## Conda 推荐工作流

```bash
conda create -n workshop-demo python=3.11 -y
conda activate workshop-demo
which python
which pip
```

只要 `python` 和 `pip` 指向同一个环境，后面的大部分安装都会清楚很多。

## 为什么镜像源有用

镜像源主要解决的是“下载慢”。

它能帮你：

- 更快下载 Python 包
- 更快下载 Conda 包
- 更快刷新 Ubuntu 软件源

它不能直接解决：

- GitHub 页面本身打不开
- 代理没有正确透传到 WSL
- SSH 认证失败

所以下载慢和 GitHub 连不上，是两类问题，不要混在一起。

## pip 换源

### 推荐写法

```bash
pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
pip config list
```

### 临时写法

```bash
pip install -i https://pypi.tuna.tsinghua.edu.cn/simple -r requirements.txt
```

### 什么时候用

- `pip install` 一直超时
- 课堂网络对官方 PyPI 很慢
- 你不想每次都手动加 `-i`

## conda 换源

### 基本配置

```bash
conda config --add channels https://mirrors.tuna.tsinghua.edu.cn/anaconda/pkgs/main/
conda config --add channels https://mirrors.tuna.tsinghua.edu.cn/anaconda/pkgs/free/
conda config --set show_channel_urls yes
```

### 查看是否生效

```bash
conda config --show channels
```

### 什么时候用

- `conda create` 很慢
- `CondaHTTPError` 经常出现
- 官方 channel 在当前网络下不稳定

## Ubuntu 系统源换源

先确认系统版本：

```bash
cat /etc/os-release
```

### Ubuntu 24.04 及更新版本

先备份：

```bash
sudo cp /etc/apt/sources.list.d/ubuntu.sources /etc/apt/sources.list.d/ubuntu.sources.bak
```

再替换：

```bash
sudo sed -i 's|http://archive.ubuntu.com|https://mirrors.tuna.tsinghua.edu.cn|g' /etc/apt/sources.list.d/ubuntu.sources
sudo sed -i 's|http://security.ubuntu.com|https://mirrors.tuna.tsinghua.edu.cn|g' /etc/apt/sources.list.d/ubuntu.sources
sudo apt update
```

### Ubuntu 22.04 及更早版本

先备份：

```bash
sudo cp /etc/apt/sources.list /etc/apt/sources.list.bak
```

再替换：

```bash
sudo sed -i 's|http://archive.ubuntu.com|https://mirrors.tuna.tsinghua.edu.cn|g' /etc/apt/sources.list
sudo sed -i 's|http://security.ubuntu.com|https://mirrors.tuna.tsinghua.edu.cn|g' /etc/apt/sources.list
sudo apt update
```

### 换完后怎么验证

```bash
apt policy
sudo apt update
```

如果输出里的地址已经变成镜像站，说明基本生效。

## WSL 网络问题的最小判断

如果你在 WSL 里操作很慢，先做这三步：

```bash
ping -c 2 pypi.org
curl -I https://github.com
echo $http_proxy
```

如果这里都不正常，优先处理网络，不要先折腾 Python 环境。

## 常见问题

### 情况 1：`pip install` 失败

优先检查：

- 是否在正确 conda 环境里
- pip 镜像是否已切换
- Python 版本是否与项目兼容

### 情况 2：`git clone` 慢

优先检查：

- GitHub 是否能访问
- 代理是否正确透传到 WSL
- 老师有没有提供 zip 包备用

### 情况 3：`apt update` 慢

优先检查：

- Ubuntu 版本
- 你改的是不是正确的源配置文件
- 是否已经备份原文件
