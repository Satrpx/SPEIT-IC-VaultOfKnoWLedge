# 操作演示

## 工作流：网页版 vs 本地 Code Agent

**网页版大模型**（如 chat.qwen.ai）适合：
- 📖 **知识检索** - 查询概念、API 文档、最佳实践
- 🔍 **信息搜索** - 需要联网获取最新信息
- 💡 **思路启发** - 头脑风暴、方案设计、代码审查建议

**本地 Code Agent**（如 Qwen Code CLI）适合：
- 💻 **实际写代码** - 直接修改项目文件
- 🧹 **重构优化** - 改进现有代码
- 🐛 **调试修复** - 定位并修复 bug
- 📁 **项目理解** - 读取整个项目结构

### 最佳实践

**✅ 应该做的：**
1. **审查生成的代码** - 至少理解框架逻辑，可以要求 AI 解释
2. **小步迭代** - 每次只改一个功能，测试通过再继续
3. **提问理解** - 不懂就问"这段代码做了什么？"
4. **版本控制** - 使用 git，便于回滚

**❌ 不应该做的：**
1. **盲目复制粘贴** - 不理解就使用
2. **一次改太多** - 问题积累难以定位
3. **完全依赖 AI** - 放弃思考和审查

## Qwen Code 基础操作

### 启动与退出

**启动 Qwen Code**
```bash
qwen
```

**继续之前的会话**
```bash
qwen -c
# 或者
qwen --continue
```

**退出 Qwen Code**
- 输入 `/exit` 或 `/quit`
- 或按 `Ctrl+D`（空输入时）

---

### 特殊按键

在交互模式中，有以下特殊按键：

| 按键 | 作用 |
|------|------|
| `/` | 显示可用命令列表（空输入时） |
| `?` | 显示键盘快捷键帮助（空输入时） |
| `Shift+Tab` | 切换审批模式（plan → default → auto-edit → yolo） |

### 什么是 Context？

**Context（上下文）** 是 AI 在对话中"记住"的所有信息，包括：
- 你之前说过的话（问题、指令、背景）
- AI 之前的回答
- AI 读取过的文件和项目结构

**为什么重要？**
- 上下文越多，AI 越了解你的项目
- 给 AI 越多相关背景，结果通常越好

**简单示例：**
```text
# 好的示例（有上下文）
这是一个 Flask 项目。请帮我添加一个用户登录功能。

# 较弱的示例（缺少上下文）
请帮我添加登录功能。
```

> **提示**：更详细的 Context 管理知识请参考 `handout.zh.reference.md`。

---

### 什么是 Session？

Session（会话）是 Qwen Code 保存的一次完整对话历史。包括：
- 你问过的所有问题
- AI 的所有回答
- AI 读取/修改过的文件

使用 `qwen -c` 可以继续之前的会话，AI 会记得之前说过的话。适合：
- 中断后继续工作
- 隔天继续同一个项目
- 切换到另一个终端继续

# 项目实战

## TODO List 实战

[下载项目zip](/lesson2/todo-app.zip)

### 项目："TODO List with Web UI"

你将使用已有的 TODO List 项目，体验完整的 Vibe Coding 循环：
**读代码 → 提问题 → 让 AI 改 → 观察结果 → 反复迭代**

### 步骤 1：打开项目并查看当前效果

**打开两个终端：**

**终端 A - 运行应用：**
```bash
# 进入项目目录
cd todo-app

# 安装依赖（第一次运行）
pip install -r requirements.txt

# 运行应用
python app.py
```

**终端 B - 启动 Qwen Code：**
```bash
# 进入项目目录
cd todo-app

# 启动 Qwen Code
qwen
```

**在浏览器打开：** http://localhost:8001

**测试当前功能：**
- 添加一个任务
- 点击复选框标记完成
- 点击 × 删除任务

> **💡 小提示**：使用两个终端可以同时进行：
> - 终端 A 运行应用，随时测试
> - 终端 B 与 Qwen 对话，添加新功能

## Vibe Coding 循环

### 步骤 2：让 Qwen 读代码（理解项目）

**目标**：让 AI 理解当前项目结构，然后你提问来理解代码。

**Prompt 1** - 让 AI 读取项目：
```
请读取并理解这个项目的结构和功能。
```

**等待 AI 分析完成后，提问理解代码**：

**问题 A**：
```
这个项目有哪些文件？每个文件的作用是什么？
```

**问题 B**：
```
当前实现了哪些功能？还有哪些功能没实现？
```

**问题 C**：
```
如果我要添加任务优先级功能，需要修改哪些文件？
```

> **Checkpoint 1** (5 分钟): 每个人让 Qwen 读取项目，然后提至少 2 个问题理解代码结构。

---

### 步骤 3：让 Qwen 修改代码（添加功能）

**目标**：基于理解，让 AI 添加新功能。

**Prompt 2** - 添加任务优先级：
```
添加任务优先级功能：
- 任务有 high/medium/low 三种优先级
- 添加任务时可以选择优先级
- 列表按优先级排序显示（high 在前）
- 用不同颜色标记优先级（红/黄/绿）
```

**观察 AI 的操作**：
- 它会读取哪些文件？
- 它会修改哪些地方？
- 它是否请求权限？

> **提示**：AI 修改文件时会请求确认，仔细查看修改内容再批准！

---

### 步骤 4：测试并观察结果

**在终端 A 中运行应用**（如果还没运行）：
```bash
# 运行应用
python app.py

# 在浏览器打开 http://localhost:8001
```

**测试新功能**：
- 添加一个高优先级任务
- 添加一个低优先级任务
- 观察排序是否正确
- 观察颜色是否正确

> **Checkpoint 2** (5 分钟): 每个人测试添加的优先级功能，确认工作正常。

> **💡 小提示**：因为你使用了两个终端，终端 B 里的 Qwen Code 还在运行，可以直接继续对话，不需要重新启动！

---

### 步骤 5：迭代改进（Vibe Coding 循环）

**在终端 B 中继续与 Qwen 对话**（不需要重新启动）：

**修复问题：**
```
优先级功能有问题：[描述你发现的问题]
请修复它。
```

**如果想继续添加更多功能：**

**添加搜索：**
```
添加搜索功能：
- 页面顶部添加搜索框
- 输入时实时过滤任务
- 匹配任务标题
```

**添加统计：**
```
添加任务统计：
- 显示总任务数
- 显示已完成数
- 显示未完成数
- 在页面顶部显示
```

> **关键**：每次只添加一个功能，测试通过后再继续！

## 总结

### 今天我们学到了什么

**一、课前准备**
- [ ] 安装 Qwen Code
- [ ] 配置 API Key（xi-ai 等平台）和 JSON 配置文件
- [ ] 验证安装

**二、知识介绍**
- [ ] **2.1 LLM 基础** - 超级文本预测器，上下文越多越好
- [ ] **2.2 Prompt Engineering** - 提供示例、逐步推理、结构化指令
- [ ] **2.3 Vibe Coding** - 描述意图，让 AI 自主完成
- [ ] **2.4 Harness Engineering** - 审查代码、运行测试、小步迭代

**三、操作演示**
- [ ] **Qwen Code 使用** - 基础按键、启动退出、Session、/ 命令

**四、项目实战**
- [ ] **TODO List 实战** - 完整的 AI 辅助开发流程

### 关键要点

1. **AI 是协作者，不是替代品** - 你引导，AI 生成
2. **上下文是关键** - 给 AI 越多信息，结果越好
3. **迭代是核心** - 第一版永远不是最终版
4. **审查代码** - AI 生成的代码需要人工审查

### 四个概念的关系

```text
Prompt Engineering → 如何问
       ↓
Vibe Coding → 如何协作
       ↓
Harness Engineering → 如何确保可靠
       ↓
Qwen Code → 使用的工具
```
